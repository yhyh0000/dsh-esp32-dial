# DSH 圆屏仪表盘 — 部署指南

把 Waveshare ESP32-S3-Touch-LCD-1.85B 变成带 Companion、Codex 控制台和 DSH 兼容应用的桌面设备。

刷入当前版本后，`Companion` 是开机默认入口，里面提供语音、邮箱和 Codex 额度三个左右滑动页面；
原生桌面和其他应用仍保留在系统中。小蓝是桌面层常驻的动画宠物，打开全屏应用时会自动隐藏。

当前 bridge 默认连接本机 Codex app-server（`codex app-server --stdio`），不再依赖
DeepSeek Harness 的旧 HTTP API。若要兼容旧 DSH，再设置 `BRIDGE_BACKEND=dsh`。

### Companion 数据源

Companion 的额度页只在配置了 Sub2API 地址时启用轮询。QQ、Gmail 和 Sub2API 的参数
现在从板载配置页填写，保存到设备 NVS；设备通过已认证的 WebSocket 发给 Bridge，
Bridge 只在内存中使用，不写入仓库或日志。服务器环境变量仍可作为没有板子配置时的
Sub2API 兼容回退：

```powershell
$env:SUB2API_QUOTA_URL = "https://your-server.example/api/quota"
$env:SUB2API_AUTH_TOKEN = "<server-only-token>"
$env:COMPANION_POLL_MS = "60000"
node bridge.js
```

Bridge 会把 Sub2API 的 5 小时窗口、7 天窗口和重置卡转换成 `companion` 帧；QQ/Gmail
通过 Bridge 主机的 IMAP 连接读取收件箱，只回传未读数、主题、发件人和时间，不回传授权码。
未配置、请求失败或字段不完整时，设备显示离线态，不会把旧数据当作实时额度。

```
┌──────────────┐     WiFi LAN      ┌──────────────┐    loopback    ┌──────────┐
│  圆屏仪表盘    │ ◄──────────────► │  Node 桥接进程  │ ◄───────────► │    DSH    │
│  (ESP32-S3)   │    WS :3082/dev   │  (bridge.js)  │  Typert RPC   │   :3080   │
└──────────────┘    token 认证      └──────────────┘               └──────────┘
```

## 第一步：跑桥接（在 DSH 所在的电脑上）

```powershell
cd D:\deepseek Harness\工作区1\dsh-esp32\bridge
npm start
```

在本仓库中运行：

```powershell
cd D:\codex\日常测试\dsh-esp32-dial\bridge
npm start
```

首次启动后打开 `http://127.0.0.1:3082/status`，应看到
`backend: "codex"`、`codexOnline: true`。Codex 桌面或 CLI 产生新 turn 后，状态会被
转换为 `working`、`thinking`、`done` 或 `error` 并转发到设备；Codex 应用会把最多 6 个会话
显示为独立 Agent 圆形按钮。

首次启动会打印：

```
bridge listening on ws://0.0.0.0:3082/dev
device token: <generated-on-first-start>   ← 仅在本机终端查看，不要提交到仓库
status page: http://127.0.0.1:3082/status
```

验证：浏览器打开 `http://127.0.0.1:3082/status` 应看到 JSON（含 `dshOnline: true`）。

## 第二步：烧固件（USB 线插板子）

当前固件由 GitHub Actions 构建，烧录页面在：
`https://yhyh0000.github.io/dsh-esp32-dial/`。点击“在线烧录”，连接设备后选择最新构建的合并固件。
也可以下载仓库 Actions 产物后使用 Espressif 工具烧录。

新固件每次启动都会保留 SoftAP 配网入口，同时尝试连接已经保存的家庭 Wi-Fi；旧 NVS 中残留的 SSID 或半截配置不会再挡住配网页面。烧录完成后按一次 RESET，等待约 5 秒即可：

1. 手机或电脑连接热点 `CODEX-DIAL-SETUP`，密码 `codexsetup`。若系统提示该网络无互联网，选择继续连接。
2. 浏览器打开 `http://192.168.4.1/`。
3. 填写 Wi-Fi、Bridge 地址/端口/token，以及 QQ、Gmail、Sub2API 参数，点击保存。
4. 设备重启并连接家庭 Wi-Fi；配网热点仍会保留，既可以继续访问 `http://192.168.4.1/`，也可以访问串口打印的家庭 Wi-Fi IP 修改配置。

QQ 使用邮箱设置中的 IMAP 授权码，Gmail 使用应用专用密码。配置保存在板子的 `dsh-config`
NVS 命名空间；表单中的密码留空表示沿用已保存值。调试时仍建议让 Bridge 只监听可信局域网，
因为当前固件使用的是 `ws://`，尚未启用 TLS/WSS。

## 验证

| 动作 | 期望 |
|---|---|
| 给板子上电 | 进入 Companion，等待 WiFi 与 Bridge 连接 |
| 左右滑动 | 依次查看语音、邮箱和 Codex 额度 |
| 等 Companion 空闲 | 显示闲置层；触摸后回到业务页面 |
| 桥接进程停掉 | 页面显示离线态，不会假装数据仍是实时的 |
