# 配网模式调研与 V1 方案

## 1. 目标

为 Waveshare ESP32-S3-Touch-LCD-1.85B 建立一条可观察、可恢复、可验收的配网链路，解决以下问题：

- 烧录后用户不知道设备是否进入配网；
- 手机连接热点后不会自动打开配置页面；
- 旧 NVS 配置会把设备带入不可见的 STA 状态；
- 配置 Wi-Fi、Bridge、QQ/Gmail 和 Sub2API 时不知道哪一步失败；
- 配置失败后没有稳定的恢复入口。

本方案针对 360 × 360 圆形屏幕，V1 只做配网和现有服务配置，不扩展服务器面板、OTA 或多设备管理。

## 2. 调研结论

### 2.1 ESP-IDF 官方方案

ESP-IDF 的 SoftAP 配网模式本质上是 AP + HTTP 配置服务，可以通过 `wifi_provisioning` 管理器接收 Wi-Fi 参数，也可以使用自定义 HTTP 页面扩展业务配置。SoftAP 方案使用 `WIFI_MODE_APSTA`，设备可以在提供热点的同时尝试连接家庭 Wi-Fi。

官方 Captive Portal 示例提供两种自动弹页机制：

1. DNS 将所有域名解析到设备 AP 地址，HTTP 请求再重定向到根页面；
2. DHCP Option 114 告诉客户端 Captive Portal 地址。

两者可以同时启用。DNS 方式对 Android、iOS、Windows 兼容性广，但不能拦截 HTTPS；因此页面仍必须保留 `http://192.168.4.1/` 手动入口。

### 2.2 WLED 和 ESPHome 的共性

成熟项目不会只依赖串口日志：

- WLED 在首次安装后明确展示 AP 名称、密码、二维码和入口地址，并支持 `4.3.2.1` / mDNS 访问；
- ESPHome 在 Wi-Fi 失败后启动备用热点和 Captive Portal，页面可以覆盖 Wi-Fi 配置，打不开自动页面时仍可手动访问 `192.168.4.1`；
- 两者都把 AP 配网作为恢复路径，而不是把配置表单藏在主业务页面里。

### 2.3 对本项目的判断

当前项目已有自定义 HTTP 配置页、NVS 配置结构、APSTA 代码和 `espressif/qrcode` 依赖，因此不需要从零引入另一套桌面系统。推荐保留自定义配置表单，补齐官方 Captive Portal 的 DNS/DHCP 能力，并新增一个独立的 LVGL 配网画面。

不建议第一阶段直接迁移到完整 `wifi_provisioning` 管理器：它适合标准 Wi-Fi provisioning，但当前产品还需要 Bridge、邮箱和 Sub2API 字段；先保留现有自定义协议，后续再评估用官方 manager 管理 Wi-Fi 部分。

## 3. 用户流程

### 3.1 首次启动

```text
烧录固件
    ↓
板子显示“配网模式”
    ↓
开启 CODEX-DIAL-SETUP
    ↓
手机连接热点
    ↓
Captive Portal 自动打开
    ↓
填写网络和服务配置
    ↓
测试并保存
    ↓
板子连接家庭 Wi-Fi
    ↓
显示成功页并进入小蓝桌面
```

### 3.2 日常重新配置

```text
小蓝桌面 / 设置
    ↓
设备配置
    ↓
板子再次显示配网画面
    ↓
手机连接热点并修改配置
```

BOOT 长按只作为硬件恢复入口，不作为唯一入口。正常运行时应当可以从设置页进入配置。

## 4. 固件状态机

```text
FACTORY
  未发现有效配置
      ↓
PROVISIONING
  AP、DHCP、DNS、HTTP 全部启动
      ↓ 保存配置
VALIDATING
  检查 Wi-Fi、Bridge、Sub2API
      ↓ 成功
RUNNING
  启动小蓝、额度、邮箱和 Codex 服务
      ↓ 失败或用户请求
RECOVERY
  重新开启 AP，保留错误原因和修改入口
```

NVS 不再只判断 SSID 是否存在，而是保存：

| 字段 | 作用 |
|---|---|
| `config_version` | 防止旧固件字段被误认为新配置 |
| `config_complete` | 标记是否完成过一次保存 |
| `wifi_valid` | Wi-Fi 参数是否可用 |
| `service_valid` | Bridge 或 Sub2API 是否至少有一项可用 |
| `last_error` | 保存失败、认证失败或连接失败的原因 |

## 5. 板端配网画面

### 5.1 等待连接

```text
        Codex Dial

        配网模式

    请用手机连接热点

    CODEX-DIAL-SETUP
    密码：codexsetup

        [Wi-Fi 二维码]

    地址：192.168.4.1

    ● 热点已开启
```

### 5.2 状态变化

| 状态 | 屏幕文案 | 颜色 |
|---|---|---|
| AP 已启动 | 热点已开启 | 绿色 |
| 手机接入 | 手机已连接 | 蓝色 |
| 页面访问 | 正在配置 | 蓝色 |
| 保存成功 | 配置已保存 | 绿色 |
| Wi-Fi 失败 | Wi-Fi 连接失败 | 红色 |
| 服务失败 | Bridge / Sub2API 不可用 | 黄色 |

屏幕只显示入口和状态，不显示邮箱密码、Token 等敏感值。配置完成后显示家庭 Wi-Fi IP 或 `codex-dial.local`。

### 5.3 二维码

二维码优先编码 Wi-Fi 加入信息：

```text
WIFI:T:WPA;S:CODEX-DIAL-SETUP;P:codexsetup;;
```

手机扫码加入热点后，再由 Captive Portal 打开配置页。二维码不能直接替代网页，因为手机必须先加入设备热点才能访问 `192.168.4.1`。

## 6. 手机配置页

### 第一步：网络

- Wi-Fi 名称；
- Wi-Fi 密码；
- 是否使用静态 IP（V1 可先不开放）；
- 扫描附近网络。

### 第二步：服务

- Bridge 主机、端口、Token；
- Sub2API URL、Token；
- 显示“已配置 / 未配置”，不回显 Token。

### 第三步：邮箱

- QQ 地址、IMAP 授权码；
- Gmail 地址、应用专用密码；
- 单独测试 QQ / Gmail；
- 邮箱未配置时不阻塞额度和 Codex 功能。

### 保存结果

保存不直接跳黑屏或无提示重启，而是返回一个结果页：

```text
配置已保存

Wi-Fi       等待连接
Bridge      已保存
Sub2API     已保存
QQ 邮箱     未配置
Gmail       已配置

设备将在 3 秒后重启
```

设备重启后继续显示配置状态，直到拿到家庭 Wi-Fi IP；成功后才进入主界面。

## 7. 技术选型

| 能力 | 方案 | 原因 |
|---|---|---|
| 屏幕 | LVGL 独立 ProvisioningScreen | 复用现有 BSP 和锁，不依赖主应用 |
| Wi-Fi | ESP-IDF `WIFI_MODE_APSTA` | 热点和家庭 Wi-Fi 可并行 |
| HTTP | `esp_http_server` | 项目已有实现，内存和接口可控 |
| 自动弹页 | DNS 全域重定向 + DHCP Option 114 | 参考 ESP-IDF 官方 Captive Portal |
| 二维码 | 项目已有 `espressif/qrcode` | 避免重新引入二维码库 |
| 存储 | NVS `dsh-config` + 版本/完整标记 | 保存后断电不丢失，可迁移 |
| 局域网发现 | mDNS `codex-dial.local` | 家庭 Wi-Fi 下减少查 IP |
| 服务测试 | 固件只做连通性与格式校验 | 详细邮箱解析仍由 Bridge 处理 |

## 8. 安全和公开仓库策略

仓库继续公开时，源码、网页和普通构建产物不能包含真实 Wi-Fi 密码、邮箱授权码、Sub2API Token 或 Bridge Token。硬编码只允许采用以下方式：

1. 本地未跟踪的 `device_build_defaults.h`；
2. 私有 GitHub Actions Secrets 注入；
3. 为单块测试板生成私有下载包。

即使仓库私有，写入固件的密钥仍可能被读取或提取，所以 V1 只把硬编码当作个人测试便利，不当作安全存储。正常运行时建议 AP 仅在配网或恢复状态开启，配置页走 HTTP 时只在可信局域网使用。

## 9. 分阶段实施

### P0：独立配网固件

- 固定 AP；
- DHCP；
- DNS 重定向；
- HTTP 根页和 404 重定向；
- 屏幕显示热点、密码、二维码、地址；
- `/api/status`、`/health`；
- 只验证 Wi-Fi 保存。

### P1：服务配置

- Bridge / Sub2API / QQ / Gmail 表单；
- NVS 版本和完整标记；
- 保存结果页；
- 服务连通性测试；
- Bridge 配置同步。

### P2：合并主桌面

- 配网成功后进入小蓝桌面；
- 设置页重新进入配网；
- 正常运行状态显示家庭 Wi-Fi IP；
- AP 在正常模式关闭，恢复模式重新开启。

### P3：云端发布

- GitHub Actions 构建；
- 构建号写入 `build-info.json`；
- 页面显示提交号；
- 手动下载 merged `.bin`；
- 每次发布保留可追溯的 SHA256。

## 10. 验收标准

| 编号 | 操作 | 预期结果 |
|---|---|---|
| P-01 | 全片擦除后烧录并重启 | 5 秒内看到配网画面 |
| P-02 | 手机连接 AP | 热点稳定可见，能拿到 `192.168.4.x` 地址 |
| P-03 | 打开任意 HTTP 页面 | 自动跳转配置页；不自动弹出时手动 IP 可访问 |
| P-04 | 扫描屏幕二维码 | 手机加入 `CODEX-DIAL-SETUP` |
| P-05 | 只填写 Wi-Fi | 保存成功，设备能连家庭 Wi-Fi |
| P-06 | 填错 Wi-Fi 密码 | 页面和屏幕显示明确失败原因，AP 保持可用 |
| P-07 | 填写 Bridge/Sub2API | 配置持久化，重启后仍存在 |
| P-08 | 断电重启 | 状态机不会回到不可见状态 |
| P-09 | 正常运行进入设置 | 能重新打开配网画面 |
| P-10 | 浏览器使用旧缓存页面 | 页面显示构建号，不允许误判固件版本 |

## 11. 最终建议

第一步只实现并验收 P0，不把邮箱、额度、Codex UI 一起带入问题排查。P0 通过后再合并 P1/P2。这样每个阶段都有一个可观察的完成标准，配网入口不会再依赖旧 NVS、串口日志或用户猜测。
